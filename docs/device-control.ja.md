# デバイスの画面を見て操作する

<p align="center"><a href="device-control.md">English</a> | 日本語</p>

コマンドや AI エージェントからデバイスを操作する機能（デバイス操作）の詳細です。

RoamRun から、デバイスの画面を確認して操作できます。できる操作は、タップ、スワイプ、文字入力、ボタンの操作です。この機能を「デバイス操作」と呼びます。**iOS / iPadOS 27 以降**が必要です。ブリッジや Xcode は使いません。RoamRun が、自前のペアリングと接続を作ります。iPhone で動かしました。iPad では試していません。

設定の前に、1 つ知っておいてください。**スイッチがオンの間は、この Mac で実行したどのプログラムでも、デバイスを見て操作できます**。使うつもりのコマンドやエージェントに限られません。詳しくは、[だれが使えるか](#だれが使えるか)にあります。

## 設定する

**設定は、デバイスごとに一度だけ行います**。デバイスを Mac と同じ Wi-Fi に接続した状態で、RoamRun のデバイスのページを開き、Device control › Set Up… を押します。デバイスでは、設定 › プライバシーとセキュリティ › デベロッパモード を開きます。「RoamRun（この Mac の名前）」を選び、Mac に表示されたコードを入力します。設定が済むと、画面に「Device control is set up」と表示されます。`roamrun status <name>` にも「Device control: connected」と出ます。

設定したあとは、デバイスが Wi-Fi 上にあって VPN 越しにつながれば、RoamRun が自動で接続します。接続を保つのは RoamRun のアプリなので、アプリを起動しておく必要があります。接続中にデバイスの Wi-Fi を切っても、接続は保たれました（iOS 27.0 で確認）。

## コマンド

```sh
roamrun look iPhone /tmp/now.png          # いまの画面を PNG で保存する。長辺は最大 1280 ピクセル
roamrun tap iPhone 295 640                # その画像のピクセルで、位置を指定する
roamrun look iPhone /tmp/now.png          # 次の操作の前に、もう一度見る
roamrun swipe iPhone 295 900 295 450      # ある点から別の点までドラッグする
roamrun look iPhone /tmp/now.png          # 1 回の look で使えるのは、tap、swipe、pinch のどれか 1 回だけ
roamrun pinch iPhone 295 640 2            # ある点を中心に 2 本指で操作する。2 で拡大、0.5 で縮小
roamrun type iPhone "hello"               # US 配列のキーで入力する。デバイスのキーボードが英語のときだけ正しく入る
roamrun paste iPhone "任意の文字列"         # デバイスのペーストボード経由で、任意の文字列を入れる。iOS が「ペーストを許可」と尋ねる
roamrun press iPhone home                 # home、lock、volume-up、volume-down
roamrun elements iPhone                   # アクセシビリティが返す画面上の要素。位置は含まない
```

## 操作の決まり

- **「見る → 操作する → もう一度見る」の順で使います**。`tap`、`swipe`、`pinch` には、直前 1 分以内の `look` が必要です。1 回の `look` で実行できる操作は、1 回だけです。ただし、`type` と `paste` は、操作のあとも同じ `look` で続けられます（見る → 入力欄を `tap` → `type`）。どちらも、直前の入力から 1 秒たつまで待ってから送ります。
- `look` は、`look 12` のように番号も出します。`tap`、`swipe`、`pinch`、`type`、`paste` に `--look <番号>` を付けると（`type` と `paste` では文字のあと）、その `look` に縛られます。あとにほかの `look`（どの呼び出し元のものでも）、ボタン、`elements`、`--look` を付けない操作があったときや、1 分を過ぎたときは断ります。付けないときは、`tap`、`swipe`、`pinch` は最後の `look` を使い、`type` と `paste` には `look` が要りません。
- 画像の向きは、デバイス内部の画面のままです。横向きのアプリは、横に倒れた状態で写りました（確認済み）。その場合も、位置はその画像のピクセルで指定します。
- `look` がデバイス自身の作る PNG を使うのは、画面のストリームから使えるフレームが得られないときです（0.14.0 以降）。デバイスがストリームを断ったとき（電話や VoIP の通話中、マイクやカメラの使用中）、フレームを読めないときや画面に合わないとき、デバイスが画面のサイズを答えないときが、これに当たります。ストリームより時間がかかります。ストリームから答えを得られないとき（応答なし・キーフレームなし・時間切れ）は、PNG を取りに行きません。接続そのものが怪しいからです。これまでどおり `look` が失敗します。この画像は、デバイスの画面表示の向きに合わせて回っています。この `look` での `tap`、`swipe`、`pinch` の位置は、デバイスを縦に持ったときの向きへ直してから送ります。ただし、次の 3 つの場合は何も送らずに断ります。1 つ目は、`look` のあとにデバイスの向きが変わっていた場合です。2 つ目は、`look` を撮る間に向きが変わった場合です（「Look again」）。3 つ目は、デバイスが横向きで、どちら向きかを答えない場合です（「Ask the user to turn it upright」）。位置を送る時点でデバイスが向きを答えないときは、その `look` のとおりに送ります。デバイスが画面のストリームを断るときは、入力をストリームなしで送ります。PNG を使ったときは、そう伝えます。`roamrun look` は標準エラー出力（`the device's PNG: …`）で、MCP の `look` は答えの文で伝えます。2026-11-26 に、閉じた iPhone Duo で試しました。Grok の音声会話中とボイスメモの録音中は、デバイスがストリームを断りました（「The device microphone or camera is currently in use」）。`roamrun look` と `roamrun mcp` の `look` は PNG を返し、そのことを伝えました。この PNG での `tap` は、縦に持ったときも、横向き（1280 x 880 の PNG）のときも、狙った所に当たりました。`look` のあとにデバイスの向きを変えると、`tap` は断られました。どちらもしていないときは、開いた状態と閉じた状態のどちらも、ストリームの画像でした。電話の通話中は試していません。
- `type` で送れるのは、最大 2000 文字です。速さは 1 秒あたり約 16 文字で、改行は Return として送られます。日本語キーボードでは、スペースも変換に使われて、入力されませんでした（確認済み）。その場合は `paste` を使ってください。
- `swipe` には、最後の引数として、かける時間をミリ秒で指定できます（50〜5000、既定は 300）。`elements` には、要素数の上限を指定できます（既定は 40）。`elements` は、読み取りの途中で画面をスクロールすることがあります。
- `pinch <名前> <x> <y> <倍率> [ms] [--rotate <角度>]` は、指定した点を中心に 2 本の指を置きます。指の間隔が始めの `倍率`（0.25〜4）倍になるまで動かしてから離します。`--rotate` を付けると、その角度（−180〜180）だけ時計回りに回します。かける時間はミリ秒で指定します（50〜5000、既定は 500）。始めと終わりのうち広いほうの間隔は、画面の短い辺の 40% です。指が画面の外に出る場合は、位置を動かさずに断ります。倍率 1 で `--rotate` を付けなければ、2 本指のタップになります。2026-11-04 に、1 台の iPhone Duo の Google マップで試しました。開いた状態では、倍率 1 で縮小し、2 で拡大し、`--rotate 45` で地図が時計回りに回りました。`pinch` の途中で Ctrl-C を押したあとも、2 本指のタップで縮小し、指は残っていませんでした。閉じた状態でも、倍率 1 と 2 は同じように動きました。`roamrun mcp` の `pinch` でも、倍率 2 で拡大しました。
- `elements` は、要素ごとにキャプションを 1 行で出します。アプリがアクセシビリティ識別子を付けた要素では、行の末尾に ` — id: <識別子>` が付きます（`com.apple.settings.airplaneMode` など）。識別子は、iPhone Duo の設定アプリでデバイスが送ってきたものから確かめました。読んだ 5 つの要素には、どれも識別子がありました。デバイスが送ってきたものに、位置はありませんでした。2026-11-06 に、同じ iPhone Duo で `roamrunctl mcp` の `elements` を試しました。設定アプリでは 12 行すべてに識別子が付き、ウィジェットの画面では、検索のウィジェットの要素はキャプションだけでした。2026-11-20 には、同じ iPhone Duo のマップアプリで `roamrun elements` と `roamrun mcp` の `elements` を試しました。どちらも識別子が出ました（`Card grabber`、`UserLocationButton` など）。

## エージェントから使う（MCP）

**エージェントからは、同じ機能を MCP のツールとして使えます**。`claude mcp add roamrun -- roamrun mcp` のように登録します。ほかのエージェントでも、同様に登録できます。ツールは `devices`、`look`、`tap`、`swipe`、`pinch`、`type`、`paste`、`press`、`elements` です。あとで説明するアプリ用の 3 つもあります。コマンドとは、次の 4 点が違います。

- `device` に渡すのは、RoamRun で付けた名前（`devices` が返す名前）だけです。Tailscale 上の名前や id は使えません。
- `look` は、ファイルに保存せず、画像と `look` の番号をエージェントに返します。
- `type` で送れるのは、1 回の呼び出しにつき 500 文字までです。
- `tap`、`swipe`、`pinch`、`type`、`paste` には、その番号を必ず渡します（`"look": 12`）。決まりは `--look` と同じです。相手の RoamRun のアプリが 0.8.0 より前のものなら、この 5 つは送りません（操作を `look` に縛らないためです）。0.8.0〜0.12 のアプリには `pinch` 以外を送れます。`pinch` は、アプリが古いという答えになります。

### アプリを入れて起動する

`install`、`install_status`、`launch`（0.11.0 以降）を使うと、Xcode なしでアプリをデバイスに入れて起動できます。`install` には、この Mac にある .ipa か .app フォルダのパスを渡します。デバイス向けにビルドして署名したものです。`install` はアプリの実行中のプロセスを終わらせてから始め、すぐに id を返します。その id で `install_status` を呼ぶと、入ったかどうかが分かります。入るまでは、そのデバイスへのほかの呼び出しには、インストール中と答えます。`launch` には、バンドル ID を渡します。ファイルは、アプリのために RoamRun 自身のフォルダへコピーされ、インストールが終わると消されます（その間にアプリが終了した場合は、次に起動したときに消されます）。途中で終了したコマンドが残したものは、アプリが動いていれば 1 時間後に消されます。.ipa は、デバイスへ送る間、まるごとアプリのメモリに読み込まれます（.app フォルダは、ファイルを 1 つずつ送ります）。

## tailnet のほかのマシンのエージェントから使う

**tailnet のほかのマシンにいるエージェントからも使えます**（0.11.0 以降）。同じツールを HTTP で提供するには、`roamrun mcp --http <ポート> --allow <who>` を動かします。`<who>` には `tag:<名前>` かログイン名を書きます。`--allow` は何回でも指定できます。`--token-file <ファイル>` を付けると、どのリクエストにも `Authorization: Bearer <ファイルのトークン>` を求めます。ファイルは自分だけが読めるもので、トークンは 32 文字以上です。この Mac 自身からの呼び出しは、トークンがあるときだけ受け付けます。Ctrl-C で止まります。この Mac の Tailscale の IPv4 アドレスでだけ待ち受け、エンドポイントは `http://<そのアドレス>:<ポート>/mcp` です。クラウドの環境にはふつう MagicDNS がないので、名前ではなくアドレスを渡してください。受け付けるのは、`tailscale whois` がそのタグを持つと答えたマシンと、そのユーザーのタグのないマシンです。リクエストの扱い、断る場合、デバイスごとの順番、ログは、`roamrunctl mcp --http` と同じです（[その決まり](roamrunctl-reference.ja.md#http-で使う-mcp)）。違いは次のとおりです。コマンドラインでデバイスを指定するのではなく、RoamRun に保存したデバイスを提供し、アプリでスイッチがオンのデバイスだけを操作します。ここでの順番が来たあとに呼び出し元が切れたり取り消したりした呼び出しは、`roamrun mcp` と同じくアプリで取りやめます。デバイスのほかの利用者の後ろでアプリの順番を待っていれば始めず、動いている途中ならきりのよいところで止めます。アップロードは、実行ごとに作るフォルダではなく、RoamRun 自身のフォルダに置きます。`roamrun mcp` と同じく、RoamRun のアプリが動いている必要があります。見せるものと送るものは、間にあるものを通ります。クラウドのプロキシには、画像、入力や貼り付けた文字、アップロードしたもの、トークンが見えます。呼び出したのは、トークンを付けたこの Mac 自身と、ログイン名で許可した tailnet のタグのない Linux マシンからです。Linux マシンからは `scripts/mcp-http-check.py` を通し、アップロード、`install`、`launch` まで進めました。`--allow tag:ci` で起動したときは、そのマシンは 403 で断られました。2026-10-27 には、tailnet に入ったクラウドの Linux マシンからも呼びました。Grok Bot のコンピューターから mcp-remote を通し、iPhone Duo で look と tap を確かめました。クラウドのプロキシを通しての呼び出しと、数百 MB のアップロードは、まだ試していません。

`--allow-install [--max-upload <MiB>]` を付けると、roamrunctl と同じように、`install` および `install_status` を提供します。呼び出し元は `PUT /upload` で .ipa を送り（既定では 1024 MiB まで）、返ってきた id と sha256 でインストールします。パスでは受け付けません。アップロードは 1 つだけ、送ってきたマシンがインストールするために置きます。アプリが始めなかったインストール（デバイスが設定されていない、スイッチがオフ、インストール中、デバイスにつながらない、アプリでの順番の前に呼び出し元が切れた）では、使われずに残ります。アップロードが消えるのは、次のときです。その .ipa のインストールを始めたとアプリが答えたとき、`ota` が保存したとき、どの呼び出し元でも次のアップロードを始めたとき、使われないまま 30 分たったとき、Ctrl-C で止めたときです。強制終了したサーバーが残したものは、1 日以上たってから消えます。消すのは、RoamRun のアプリが動いている間か、アプリが起動したときです。`--allow-install` か `--allow-ota` を付けたサーバーが起動したときにも消します。`--allow-install` も `--allow-ota` も付けなければ、どちらもありません。

代わりに `--allow-ota` を付けると、OTA server になります。ツールは `ota` の 1 つだけで、`roamrun ota` がファイルを載せるのと同じように、アップロードを [OTA のページ](../README.ja.md#ブリッジを使わずにインストールするota)に載せます。CI のジョブがビルドを公開するためのもので、デバイスは操作しません（[ota.ja.md](ota.ja.md#ci-のジョブから)）。2 つのフラグは、ポートを分けた 2 つのサーバーに付けます。

## 操作している間のデバイス

**操作している間、デバイスでは画面共有のセッションが動きます**。`look` や操作のたびにセッションが始まり、RoamRun は最後の操作から約 5 秒間、そのセッションを保ちます。デバイスには、画面共有として表示されました（確認済み）。セッション中の音とマイクの様子は、一度の試行でアプリごとに記録してあります。音が鳴り続けたアプリもあれば、再生は続いても聞こえなくなったアプリ、再生の止まったアプリも 1 つありました。音声入力は何も拾いませんでした。詳しくは [sound-while-looking.md](sound-while-looking.md)（英語）にあります。

## だれが使えるか

デバイス操作は、特定のエージェントやコマンドだけに許可されるものではありません。スイッチがオンの間は、**この Mac で実行したどのプログラムでも、アプリを通じてデバイスを見て操作でき、アプリを入れて起動もできます**。ビルドスクリプト、パッケージのインストール処理、別のエージェントも含まれます。`look` には、画面に出ているものがすべて写ります。通知やメッセージも例外ではありません。デバイスをロックしても、操作は止まりません。ロック画面も見えて、操作できました（確認済み）。ただし、ロックの解除には、パスコードか Face ID が必要です。**HTTP の MCP サーバー（上で説明した `mcp --http`）が動いている間は、`--allow` で許可したマシンのどのプログラムでも、同じことができます**。許可したログイン名のタグのないマシンと、許可したタグのマシンのすべてが対象で、スイッチがオンのデバイスすべてを操作でき、`launch` も使えます。`--allow-install` を付けると、デバイス向けに署名されたどのアプリにも入れ替えられます。OTA server（`--allow-ota`）はデバイスを操作しません。許可したマシンにできるのは、Ad Hoc か Enterprise のビルドを OTA のページに載せることで、載せたビルドは tailnet の誰でもインストールできます。マシンのほかに確かめるのは、`--token-file` のトークンだけです。

- デバイスのページの Device control の横にあるスイッチで、すべてのプログラムからの操作をまとめてオフにできます。もう一度押すと、オンに戻ります。Set Up と Pair Again のあとは、スイッチがオンになっています。`roamrun key import <file>` と `roamrun pair control --with <Tailscale name>` のあとも同じです。自分の作業でデバイスを使っていないときは、オフにしてください。
- `look` で保存したファイルは、本人だけが読めます。削除するまで残ります。
- 接続のたびに、Mac とデバイスは互いを検証します。デバイスのアドレスで別のものが応答した場合は、接続を拒否し、入力も送りません。
- ペアリングには、秘密鍵が含まれます。鍵の保管のしかたと、鍵を使える範囲は、[SECURITY.md](../SECURITY.md)（英語）にあります。
- デバイス操作を取り消すには、デバイスのデベロッパモードの一覧から、RoamRun の項目を削除します。

## 離れた Mac でデバイス操作を使う

設定には、Mac とデバイスが同じ Wi-Fi にあることが必要です。データセンターの Mac のように、離れた場所にある Mac は、この条件を満たせません。2 台の Mac が同じ tailnet にあれば、デバイスと同じ Wi-Fi にある Mac（以下、デバイスのそばの Mac）が仲介して、離れた Mac が自分のペアリングを作れます。離れた Mac は、そのペアリングを暗号化して保管します。デバイスのそばの Mac は、デバイスの通信の中身を読まずに中継し、何も保存しません。ただし、入力するコードは、デバイスのそばの Mac に表示されます。仲介には、信頼できる Mac を使ってください。

```sh
roamrun pair control --with macbook-pro              # 離れた Mac で実行する。RoamRun のアプリを開いておく
roamrun pair introduce --host cloud-mac --to iPhone   # デバイスのそばの Mac で、自分で実行する。iPhone は、デバイスのそばの Mac の RoamRun での名前
roamrun look iPhone                                  # 離れた Mac で、ペアリングできたと表示されたあとに実行する
```

`macbook-pro` はデバイスのそばの Mac、`cloud-mac` は離れた Mac の、Tailscale 上の名前です。デバイスで「cloud-mac」を選び、`pair introduce` が表示したコードを入力します。`pair introduce` は、自分のターミナルで、自分で実行してください。エージェントに実行させると、コードがエージェントの出力に入ってしまいます。

- 離れた Mac は、デバイスのそばの Mac を最大 10 分待ちます。そのあと、ペアリングを最大 9 分待ちます。
- コードを間違えると、`pair introduce` は終了します。離れた Mac のコマンドは終了しません。`pair introduce` をもう一度実行すると、離れた Mac が新しいコードを作ります。試せるのは、全部で 5 回です。
- 離れた Mac では、ログインしたセッションで RoamRun のアプリを開いておく必要があります。Xcode は要りません。デバイスをあらかじめ保存しておく必要もありません。
- 離れた Mac に、そのデバイスとの有効なペアリングがすでにある場合、仲介は始まりません。先に、離れた Mac のデバイスのページで、そのペアリングを削除してください。
- 結果がデバイスのそばの Mac に届かなかった場合は、離れた Mac で `roamrun pair control --last` を実行すると、直前の試行の結果を確かめられます。

2 台の Mac の間に Tailscale がない場合は、デバイスのそばの Mac でペアリングを作り、ファイルとして運びます。

```sh
roamrun key create iPhone ~/iphone-for-cloud.json --as cloud-mac   # デバイスのそばの Mac で実行する。デバイスで「cloud-mac」を選び、コードを入力する
roamrun key import ~/iphone-for-cloud.json                         # 離れた Mac で、RoamRun のアプリを起動した状態で実行する。デバイスとのペアリング情報を保存し、ファイルを削除する
```

このファイルには、ペアリングの秘密鍵が含まれています。ファイルを持っていて、デバイスに接続できる人は、だれでもデバイスを見て操作できます。パスワードと同じように扱い、コピーを残さないでください。`key import` は、接続できた場合にだけペアリングを保存します。そのため、取り込むときに、デバイスに接続できる必要があります。

ファイルを作ったあとにデバイスが再起動していると、デバイスのポートが変わっています。離れた Mac にまだ保存していないデバイスなら、`key import` がポートを探します。すでに保存してあるデバイスの場合は、先にデバイスのページの Find RemotePairing Port を使ってください。

この方法で作ったペアリングは、デバイスのデベロッパモードの一覧に、それぞれの名前で表示されます。デバイスで 1 つずつ削除できます。

何もない状態の Mac に、Tailscale、RoamRun、ペアリングをまとめて用意する手順は、[another-mac.md](another-mac.md)（英語）にあります。そのためのスクリプトも付いています。
